# 使用统计

轻量记录每个人的 AstrBot 指令调用、LLM token 用量与高频时段。群排行只比较指令次数。

## 指令

| 指令 | 输出 |
| --- | --- |
| `/使用统计` | 个人累计指令次数、LLM 调用次数、已知总/输入/输出 token、用量缺失次数、指令和 LLM 高频小时段、常用指令 |
| `/使用统计 指令 [页码]` | 每条注册指令的累计次数，每页 10 条 |
| `/使用统计 模型 [页码]` | 按 Provider 与模型区分的次数、token、失败与用量缺失次数，每页 8 条 |
| `/使用排行` | 当前群的累计指令次数排行图片，以及自己的本群名次；私聊不可用 |

普通用户只能通过上述指令查询自己的个人明细。群榜展示该群成员昵称、用户 ID 和本群指令次数。
查询指令本身也计数，返回结果包含本次查询。相同次数并列排名，显示顺序按用户 ID 稳定排序。

## 统计口径

- 从安装并初始化成功后开始累计，不能补算安装前历史。个人汇总覆盖当前平台实例、当前机器人下的所有群聊与私聊；不同平台实例、机器人、用户相互隔离。
- 指令在实际进入框架处理函数时记一次，包括处理函数随后报错的调用。未识别文本、参数解析失败、权限过滤拒绝、前置门禁阻止且未执行的指令不计。
- **按 AstrBot 注册指令统计**，同一指令别名合并，正式注册的指令组子命令分别计数。若其他插件自行在一个处理函数内解析参数，例如 RP 的 `/rp 统计` 与 `/rp 排行榜`，会合并到 `/rp`；不猜测参数是不是子命令，也不保存参数。正则/普通消息监听器及 LLM 工具不算注册指令。
- LLM 以配置的 AstrBot Provider 的 `text_chat` / `text_chat_stream` 一次调用为单位，包括默认聊天、工具循环每轮、在消息处理期间由插件直接调用 Provider / `context.llm_generate` / `context.tool_loop_agent` 的路径。
- token 读取 Provider 返回的实际 usage，包含缓存输入和 Provider 已报告的推理消耗。输入+输出为总量；不重复加缓存或 reasoning 明细。供应商未返回用量、失败没有用量、流式未收到最终完整用量时，记为“未返回总用量”，不按文本长度估算，也不伪装成已知 0。
- 流式只采纳最终非 chunk 响应的 usage，不将流片段与最终累计重复相加。失败/取消会增加调用及失败次数；已有完整最终 usage 则保留，否则记用量未知。内部重试没有暴露 usage 的收费无法补计，统计值不是供应商账单。
- 指令时段取进入处理函数时间，LLM 时段取 Provider 调用完成/失败时间，固定使用北京时间（UTC+8）。24 个小时桶跨日期累计，展示最频繁的前三个小时段；不保留按日、按周、逐次时间线。
- 不覆盖直接使用第三方 SDK / HTTP 的模型调用、语音/向量等非聊天 Provider、安装前已缓存的旧 bound method，及消息生命周期结束后的独立后台任务；这些路径无法可靠归属到一个用户。

## 安装与配置

当前为本地初版，无远程仓库地址。将插件目录放入 AstrBot 的 `data/plugins/astrbot_plugin_usage_stats/`，依 AstrBot 流程安装 `requirements.txt` 依赖并重载插件。
依赖仅 `Pillow>=10.0`；SQLite 使用 Python 标准库。没有模型请求、额外服务、字体下载或头像下载。

当前声明 **AstrBot >=4.29.1,<5**，依据官方 4.29.1 源码核对接入点。内部接口在未来版本仍可能变化，运行时会检查并显示统计异常，不能将这个范围视为所有未来版本都已验收。
核心依据及限制见 [兼容性说明](docs/compatibility.md)。

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `max_database_mib` | 64 | 数据库文件上限，范围 1–1024 MiB；SQLite 回滚日志有短暂额外占用 |
| `leaderboard_size` | 10 | 排行人数，范围 1–20 |
| `font_path` | 空 | 可选中文字体路径；自动检测微软雅黑、Noto CJK、文泉驿等系统字体，缺失时发送文字排行 |

排行榜采用 RP 当前排行榜的深色标题、浅色圆角卡片、前三名强调与右侧大数值结构。图形代码独立实现，不复制 RP 字体、图片或图标；圆头像使用昵称首字。
设计参考：[astrbot_plugin_rp_taikover](https://github.com/RioMaker/astrbot_plugin_rp_taikover)。

## 存储与维护

数据位于 `data/plugin_data/astrbot_plugin_usage_stats/usage.db`，不写入插件代码目录。

- 一个用户一条总计和两组固定 24 小时数组；用户与指令、用户与模型、用户与群各保存累计记录。
- 不保存聊天、提示词、回复、指令参数、密钥、逐次调用日志或每日快照。相同用户重复调用已有指令更新原有记录；空间主要随用户、指令、模型及群关系的种类增长，不随每次调用线性增长。
- 每次写入单独原子事务，线程锁与 SQLite 事务锁保护并发；重启保留累计。使用 DELETE journal，避免长期增长的 WAL。
- 数据库默认硬上限 64 MiB。达到上限或写入失败时保留已有数据、回滚当次事务，并尽力将异常持久化到预留状态记录；查询会提示数据可能缺失。增加容量并重载后可继续写入，漏记的数据不能凭空恢复，历史异常提示会保留。
- 限额只限制数据库文件。事务中会产生短暂回滚日志；磁盘完全不可写时无法保证异常状态也能落盘。不会自动删除用户累计来腾空间，不自动执行 VACUUM。
- 图片在内存生成并发送，无图片目录、永久头像缓存或后台定时任务。图片渲染串行以限制 Pillow 并发占用。
- 备份：停止/卸载插件后复制 `usage.db`；恢复时停用插件后放回同一路径。不要只备份一个正在进行事务的数据库文件。
- 统计接入在插件加载期间作用于运行实例；卸载/重载会恢复自己的包装。依赖群会话配置隐藏查询指令，不等于卸载全局统计接入。

2026-10-18 本机模拟磁盘测量：空库 32 KiB；同群 651 名用户，每人 10 种指令与 2 个模型各记录一次后为 724 KiB；随后其中 73 人各重复 100 次已有指令，额外 7,300 次写入后仍为 724 KiB。测量使用真实临时文件及 FULL 同步事务，事务结束后日志占用为 0；这不是线上容量或性能保证。
